# 抖X账号权限名单

模块从 Gitee 主源读取签名名单，GitHub 提供备用副本。公开数据只有 UID 的 SHA-256 标识，不保存明文 UID、令牌或私钥。

## 在模块中管理

1. 管理员从“账号与授权 → 管理员名单管理”进入，也可从模块独立设置打开“名单管理”。
2. 首次填写自己的抖音 UID 和 Gitee 仓库级私人令牌：仅选择 `shijiudada/douyinmodule-access`，勾选 `projects`（`user_info` 为平台必选）。凭据仅在模块应用中通过 Android Keystore 加密，保存在不参与备份的目录。
3. 输入一个或多个 UID，选择加入黑名单、加入白名单、移出名单。切换黑白名单会自动移除另一边；整批校验通过才上传。上传前显示操作预览。
4. “读取名单与发布进度”区分已上传提案和已发布签名版本。任务每5分钟尝试发布；GitHub调度和网络缓存可能延迟，不能保证5分钟内生效。读取到发布版本才算完成。

管理员名单控制客户端入口，**真实服务器写权限由 Gitee 仓库授权决定**，不能把上报 UID 当作服务器身份认证。新增管理员需要同时授予其 Gitee 仓库权限；撤销时也必须撤销其仓库权限/令牌。至少保留一位管理员。请勿共享管理员令牌。

## 发布流程

- Gitee `policies/proposal.json` 保存待发布快照，管理员通过 API 携带文件 SHA 更新；遇到并发修改必须重新读取，不覆盖他人的变更。
- GitHub Actions 校验格式、黑白名单冲突、版本和管理员列表，使用私有 Secret 中的 RSA 私钥签名，再更新 Gitee `policies/access.json` 与 GitHub 同名文件。
- 模块固定公钥验证签名，拒绝无效签名、旧版本和同版本不同内容；写入缓存采用 AtomicFile。签名覆盖版本和三张名单，Git 提交记录时间和操作者；时间戳不作为安全判断依据。
- 私钥只用于发布任务，不进入 APK 或 Git；Gitee 授权也不进入 APK、公开名单、日志、Intent 或配置备份。
- 旧110版忽略新增字段，继续读黑白名单；新版只消费已签名名单。不要再手动编辑发布结果文件。

网络失败保留最近有效名单。黑名单优先并停用模块；恢复后重启抖音恢复全部效果。白名单提供模块 VIP 资格，功能分类另行安排，不涉及抖音官方付费权益。

## 本地备用管理

`python3 manage.py white add`（也支持 black/white/admin 与 add/remove）会隐藏输入 UID 和 Gitee 令牌，读取最新提案并以 SHA 校验更新 Gitee。只保存哈希，不修改已发布文件。发布器通过 `python3 -m unittest test_publisher` 校验；GitHub Secrets 需要 `GITEE_TOKEN` 与 `POLICY_SIGNING_KEY`。

签名验证保护名单来源和传输后的内容完整性，不能阻止拥有仓库写权限的受信管理员提交名单，也不能把运行在用户控制设备上的模块变成不可修改的授权系统。
